# Issue/Defect Report


본 프로젝트는 개발 및 테스트 단계에서 발생하는 모든 결함과 불일치 사항을 체계적으로추적하고 해결하기 위해 문제 해결 관리 프로세스를 도입합니다. 식별된 이슈는 누락 없이 기록되며, 근본 원인 분석을 통해 재발을 방지합니다.


**[문제 해결 프로세스 흐름]**


**Step 1. 문제 식별 및 등록 (Identification)**


테스트 중 발견된 버그나 하드웨어 이슈를 Notion에 등록


**Step 2. 원인 분석 (Analysis)**


PM이 이슈의 근본 원인 분석


**Step 3. 해결 및 검증 (Resolution & Verification)**


담당자가 코드를 수정(Pull Request) 또는 하드웨어를 변경한 후, 교차 검증을 통해 정상 동작 확인


**Step 4. 종료 (Closure)**


문제 해결이 최종 확인되면 이슈 티켓을 Closed 상태로 전환


**[Issue Ticket 명세 양식]**


모든 이슈는 아래의 양식을 기준으로 기록 및 관리됩니다.


| **항목**                 | **세부 내용**             | **예시**                              |
| ---------------------- | --------------------- | ----------------------------------- |
| **Issue ID**           | 이슈 고유 식별 번호           | BUG-001                             |
| **분류 (Label)**         | 발생 영역 구분              | 하드웨어 / ROS 2 통신 / 인지 알고리즘           |
| **근본 원인 (Root Cause)** | 현상 이면에 있는 기술적 원인      | PWM 신호 매핑 범위 설정 오류 (0~255 스케일 불일치)  |
| **해결방안 (Resolution)**  | 수정된 내역 및 관련 Commit 내역 | 아두이노 모터 제어 코드 내 map() 함수 파라미터 수정 완료 |


# **[명명 규칙]**


**[SYS/HW/SW] - [목적] - [번호]**

- [SYS/HW/SW]
	- SYS: HW + SW 전반에 걸친 문제사항
	- HW: HW에 국한된 문제사항
	- SW: SW에 국한된 문제사항
- [목적]
	- CR: 변경
	- REQ: 요청
	- ERR: 오류 (중요!)
	- BUG: 어려움, 차질, 지연(딜레이)
- [번호]
	- 순차 번호
