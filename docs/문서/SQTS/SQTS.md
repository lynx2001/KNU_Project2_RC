**1. 개요 (Scope)**


**1.1 목적 (Purpose)**


**본 문서는 자율주행 로봇 플랫폼 시스템에 대한 시스템 적격성 검증 명세서(System Qualification Test Specification, SQTS)이다.**


**SYS.5 프로세스(ISO 15288 / Automotive SPICE)에 따라 시스템이 이해관계자 요구사항 및 설계 기준([4.0] 아키텍처)을 충족하는지를 공식적으로 검증하기 위해 작성되었다.**


**1.2 적용 범위 (Scope of Application)**


**본 명세서는 다음 하드웨어 및 소프트웨어 구성 요소에 대한 시스템 수준의 통합 테스트 및 적격성 검증에 적용된다.**


| **계층 (Layer)**   | **구성 요소**    | **주요 부품**                                                    | **역할**                      |
| ---------------- | ------------ | ------------------------------------------------------------ | --------------------------- |
| Layer 1 – 구동부    | 모터 / 조향 / 전원 | JGB37-520 DC 모터, LD-1501MG 서보, 11.1V Li-Po 배터리, STM32        | 후륜 구동 및 전륜 조향, 전원 분배        |
| Layer 2 – 연산/제어부 | 상위/중위/하위 제어기 | Raspberry Pi 4, STM32, Arduino Mega 2560                     | 자율주행 판단, 모터 PID 제어, 실시간 I/O |
| Layer 3 – 인지부    | 센서 / 카메라     | RPLiDAR A1, Pi Camera V2, HC-SR04 (×12)                      | 환경 인식, 거리 측정, 차선 검출         |
| SW 아키텍처          | ROS 2 노드 계층  | lidar_node, camera_node, autonomous_node, serial_bridge_node | 인지→판단→제어 데이터 파이프라인          |

**4. 시스템 개요 (System Overview)**


**본 시스템은 3-Layer 계층 구조로 설계된 자율주행 로봇 플랫폼이다. Raspberry Pi 4를 상위 제어기로 하여 ROS 2 기반 자율주행 알고리즘을 실행하며, STM32가 정밀 모터 제어를 담당하고, Arduino Mega 2560이 실시간 센서 I/O 및 긴급 제동(AEB)을 처리한다.**


**4.1 물리 아키텍처 요약**


| **Layer**    | **구성**              | **내용**                                                                                      |
| ------------ | ------------------- | ------------------------------------------------------------------------------------------- |
| Layer 1 – 구동 | Actuators + 전원      | JGB37-520 후륜 DC 모터, LD-1501MG 전륜 서보, 11.1V 5000mAh Li-Po 배터리 → STM32 경유 전원 분배               |
| Layer 2 – 제어 | Computing & Control | Raspberry Pi 4 (ROS 2, SLAM, 비전), STM32 (PID, PWM, 오도메트리), Arduino Mega 2560 (초음파, AEB, 부저) |
| Layer 3 – 인지 | Sensors             | RPLiDAR A1 (360° 스캔, USB 3.0), Pi Camera V2 (차선 인식, CSI), HC-SR04 ×12 (전/후/좌/우 초음파)         |


**5. 테스트 전략 (Test Strategy)**


**5.1 테스트 접근 방식**


**본 SQTS는 Bottom-Up 통합 검증 접근법을 채택한다. 개별 컴포넌트(하드웨어/소프트웨어 단위) 수준 검증을 완료한 후, 서브시스템 통합, 최종 시스템 수준의 적격성 검증을 순차적으로 수행한다.**


**5.2 테스트 유형 정의**


| **테스트 유형**       | **목적**                        | **대상**                                |
| ---------------- | ----------------------------- | ------------------------------------- |
| 기능 시험 (FT)       | 각 기능 요구사항이 명세대로 동작하는지 확인      | SLAM, 차선 인식, AEB, 부저 경고, 모터 제어 등      |
| 인터페이스 시험 (IT)    | 서브시스템 간 통신 및 데이터 규격 적합성 확인    | UART, USB, CSI, ROS 2 토픽, GPIO 신호     |
| 성능 시험 (PT)       | 처리 지연, 응답 시간, 제어 정밀도 기준 달성 확인 | LiDAR 주사율, 카메라 FPS, AEB 응답 시간, PID 수렴 |
| 안전 / 신뢰성 시험 (ST) | 비정상 상황 및 안전 기능 동작 확인          | 퓨즈/스위치 동작, 긴급 제동, 전원 단선 시 거동          |
| 환경 시험 (ET)       | 연속 운용 및 열 환경 안정성 확인           | 연속 동작 시 RPi 4 CPU 온도, 팬 동작            |


**5.3 합격 기준 (Pass/Fail Criteria)**


**PASS: 테스트 케이스에서 정의된 예상 결과와 실제 결과가 일치하거나 허용 오차 범위 내에 있는 경우**


**FAIL: 예상 결과와 실제 결과가 허용 오차 범위를 벗어나거나 시스템이 비정상 동작(크래시, 무응답, 오동작)하는 경우**


**BLOCK: 선행 조건 미충족으로 테스트를 진행할 수 없는 경우 (별도 기록 후 재검증)**
